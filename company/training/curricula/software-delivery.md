# Curriculum — Software delivery (end-to-end)

Objective: be able to take an idea to a shippable, sellable product.

## Modules
1. **Problem brief** — one page: user, problem, why now, success metric.
2. **Scope** — MVP vs later; explicit non-goals. `knowledge/products/<slug>/scope.md`.
3. **Build** — working code in a repo, versioned, with tests that run.
4. **Docs** — README, quickstart, license, changelog.
5. **Demo** — a reproducible 2-minute demo (script + screenshots or a short clip).
6. **Package** — pricing sheet, delivery format, support terms draft.
7. **Sale-readiness check** — can a stranger buy and use it from the docs alone?

## Acceptance
A stranger can clone, run, and understand the product from docs alone; the demo
is reproducible; the pricing sheet exists. Buyer artefacts carry no secrets.
